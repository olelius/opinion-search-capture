## 用户操作流程

1. 启动：通过 `paths.application_root/default_config_path/default_output_root` 定位数据。源码模式位于仓库；便携 EXE 模式位于 EXE 所在目录，均不依赖启动 cwd。存在默认 `.local/plan.json` 时只读自动加载，否则明确引导填写关键词、输出目录或加载文件。加载不执行任务。
2. **采集设置**：计划名称、项目名称、逐行关键词、TOP N、平台/APP-WEB/结果-下拉词。设备按钮在后台调用 `android.discover_devices()`，显示设备名称并把串号存入下拉框数据；离线/待连接设备有标签、禁用选择。单台在线设备且无已保存串号时可自动选中；已保存设备消失时保留串号和“未发现”提示，不静默改选另一台。
3. **导出与预检**：原图目录/文件名、拼图目录/文件名独立保留，拼图列数 1—100。每个模板都有中文字段下拉插入器，插入当前光标/选区，月份、日期、批次和页码可选两位数字。新布局、单元宽度、像素/高度上限与捕获超时、重试参数仅在 Plan 已支持时启用；旧配置及未编辑的小数精度保持原值。
4. 点击“预检真实导出路径”：后台调用 `export_plan.preflight_plan(Plan.from_dict(data))`，默认 `probe_writable=False`。表格显示核心实际计算的原图/拼图路径及平台、端、内容、关键词，不用 JSON 冒充路径预览。长路径可悬停查看或双击追加到可复制详情。错误、警告、数量及边界保留核心说明。编辑配置后立即清空失效路径，晚到的旧快照结果丢弃。
5. **保存配置**：首次保存选择 JSON；“保存配置”指向已加载/保存的同一文件，并明确询问覆盖，默认选择否；“另存配置”同样确认已有目标。覆盖采用临时文件写完后原子替换；失败保留原文件。接口只接受 `.json`，不用于图片。采集图片的不覆盖发布仍由核心负责。
6. **执行一次**：冻结配置，后台运行。任务数多时使用 `QTableView + QAbstractTableModel`，按平台/端/内容/完整关键词身份更新，区分 A1/A10、结果/下拉词。进度“已处理”包含失败和受阻，不等于成功。成功、未完整验收、受阻、失败、取消等中文显示；未知状态明确未知，原始结果保留。阶段标签仅展示核心上报的当前阶段与耗时，不替代任务终态。
7. **取消本次**：设置传给核心的 `threading.Event`，保持“正在取消”和执行禁用，直至核心保存状态、工作线程实际结束。没有 terminate/强杀或在 GUI 主线程阻塞 wait。
8. **计划时间**：窗口和固定时刻可增删，跨午夜语义沿用核心。只有点击“启动计划”才创建并启动服务；单次执行与计划互斥。启动后使用快照，停止后才重新开放配置编辑。
9. **任务与历史**：后台读取 `storage.list_batches(output_root, limit=200)`；本次任务、有限长度日志、可筛选/排序的历史列表分离。选择历史后以本地文件 URL 打开存在的输出目录/报告，不通过 shell。恢复动作须确认，使用历史 `config`（兼容 `config_json`），传 `resume_batch_id`；不使用当前编辑内容修改旧批次。成功/运行中的批次不重复恢复；缺历史快照时明确提示。

## 停止、关闭与托盘合同

| 操作 | 核心动作 | 窗口表现 |
| --- | --- | --- |
| 停止计划，等待当前完成 | `stop(wait=False, cancel_running=False)` | 停止未来接收，等待当前自然结束；服务仍运行时不恢复执行按钮 |
| 停止并取消当前 | `stop(wait=False, cancel_running=True)` | 请求协作取消并等待；已请求普通停止后仍可升级为取消 |
| 默认关闭窗口 | 停止计划并取消单次/在途任务 | 暂缓关闭，保持可见；服务、执行线程及只读线程全退出后自动关闭 |
| 显式启用托盘后最小化/关闭 | 不停止服务、不取消任务 | 隐藏到托盘继续；双击恢复 |
| 托盘“停止计划、取消任务并退出” | 取消并停止，等实际退出 | 恢复窗口显示退出进度，不假退出 |

托盘默认关闭，本机无托盘支持时启用动作撤回并提示，窗口保留。服务构造/start/stop 由 `ScheduleThread` 执行；Qt 信号回到 GUI 更新控件。服务 `last_error` 会保留为异常退出，不被“线程结束”覆盖成正常停止。

## 核心接点

- `run_core(data, *, cancel_event=None, progress_callback=None, resume_batch_id=None)` 转换 Plan 后调用 `runner.run_plan`。GUI 不传实际 collector。测试可注入 dict 执行器；旧单参数替身按签名兼容，但不会捕获 TypeError 后重复执行。
- `ScheduleService(plan, progress_callback=...)`；服务线程通过 `is_running` 判断真正退出。
- 任务事件接受 `batch_started/task_started/task_retry/task_reused/task_finished/composites_finished/batch_finished/schedule_*`；任务完整身份由 `capture_kind` 等字段区分；批次最终事件触发只读历史刷新。
- 预检是代表性路径计算，实际 `captured_at/artifact_id/part_count/status` 尚未知；预检通过不证明未来可写、无冲突、已完成分页或已得到图片。实际执行仍由核心重新校验并排他发布。
- 正常网页登录/profile 管理由平台与主智能体整合。本子任务未新增自动登录、风险绕过选项或不对称的半成品登录按钮；小红书登录按用户决策暂缓。
