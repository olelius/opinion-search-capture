# 复用现有Chrome

> 本页仅说明可选高级模式。产品默认采用“独立网页会话”：打开平台→正常登录一次→保存并复用会话。默认模式已在本机实际完成小红书双关键词采集，不依赖日常Chrome调试设置。

## 连接方式

在程序的网页会话设置中选择“复用已打开的Chrome”，端点保留“自动发现”。此模式使用独立程序自己的常驻连接，不依赖Codex，不打开新的登录窗口，也不复制日常浏览器的登录资料。

Chrome 144及以上支持原生现有会话连接。首次需由使用者在当前Chrome打开 `chrome://inspect/#remote-debugging`，启用调试，并在Chrome提示时允许本机程序连接。该授权可访问浏览器页面及登录会话，应仅授予信任的本机程序；程序不自动改变这项设置。[Chrome官方说明](https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect)

Windows自动发现仅按Chrome官方连接格式读取 `DevToolsActivePort` 中的端口和连接路径，不枚举资料目录，不读取Cookie、Preferences或密码数据库。高级用户也可填写明确的本机HTTP/WebSocket调试端点；外网地址、带认证信息的地址及无关路径会被拒绝。[官方实现参考](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/src/browser.ts)

## 请求控制

- 同一连接和平台标签页跨关键词、批次复用；同词已在正确结果页时不再提交搜索。
- 更换关键词才执行必要搜索；下拉词同值仅展开，异值只输入一次，不进入笔记/视频详情页。
- 计数、DOM布局读取、图片裁切/拼接均在本地进行。仅为加载目标结果进行必要滚动，到达TOP N后停止。
- 同一批次中，一个平台/端返回登录、验证或风险门槛后，后续同会话关键词直接记录受阻，不重复发请求；其他平台继续。使用者处理问题并明确恢复批次后，才重新尝试未完成项。
- 工作进程只负责截图任务，取消或超时只回收程序自有进程树。退出本程序仅断开连接，不关闭用户Chrome、标签页或登录会话。

## 当前边界

现有Chrome工具实拍样例已留存；独立程序的高级原生连接未实连验证。此次工具禁止打开原生调试设置后即停止该路线，没有通过其它界面启用；最终业务验证使用程序正常专属登录会话，不将两种连接混称。

“独立网页会话”是默认模式。程序启动时不自动截图，定时功能需要在界面启动计划并保持程序运行；首次登录或登录过期时再引导用户正常登录。
