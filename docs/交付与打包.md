## 3. 便携布局及入口约定

纠正构建生成的onedir布局：

```text
H:\Public Opinion Search Capture System\dist\candidate-<BUILD_ID>\OpinionCapture-Portable\
  OpinionCapture.exe                 # windowed；默认双击只开GUI
  OpinionCapture-CLI.exe             # console；CLI与Android worker保留stdout
  _internal\                        # 两入口共享运行库、Qt插件及第三方资源
    portable_resources\
      portable-defaults.json
      portable-dependencies.example.json
```

应分发整个目录，不只发一个 EXE。构建不把开发机 `.local` 或用户数据复制进去。运行后用户数据在 EXE 旁 `.local`，只读资源在 `_internal`；解压目录需可写，不以管理员运行掩盖目录权限问题。

用户界面与 CLI：

- `OpinionCapture.exe` 无参数：构造 `MainWindow(config_path=...)`，不调用 `run_plan` 或启动定时服务。
- `OpinionCapture-CLI.exe` 保留 `gui / preview / run / watch / history / init-config`；只有显式 `run` 或 `watch` 才执行采集或开启调度。
- 两入口均接受 `--config`。显式相对配置路径按调用者 CWD 解析；省略时使用核心 `paths.default_config_path()`。默认输出目录使用 `paths.default_output_root()`。
- `run --resume-batch ID` 透传核心；其他 action 带此参数会报参数错误，不退回 GUI。
- `init-config` 使用通用示例，排他创建目标文件，已有文件保持原样。
- 需要终端输出、重定向或退出码时使用 `OpinionCapture-CLI.exe`。windowed 入口的诊断写 EXE 旁 `.local\packaging\launcher.log`。

## 4. 与主及 Android agent 已确认的 worker 接口

### Android

已与 agent `01a0815f-1d3b-7470-b5b0-432b4dfaf13b` 确认：

```text
OpinionCapture-CLI.exe --ui-worker JSON
```

- JSON 是一个命令行参数，`subprocess` 传参数列表，不经 shell 拼接。
- launcher 在任何 GUI/CLI 业务路由之前 `json.loads` 并调用 `opinion_capture.android._ui_worker(payload)`；stdout 专用于该函数的 JSON，异常非零退出，不添加进度日志到 stdout。
- Android agent 负责冻结分支选同目录 console companion；缺少 companion 显式报告，不把 windowed EXE 当通用 Python。
- 源码 Windows 分支保持 base Python 加项目 src/venv site-packages；杀死测试需要确认 **实际执行 PID 就是被等待/终止 PID**。只杀 venv pythonredirector 可能留下真正的 Python 子进程。

### 小红书 WEB

launcher 同时接受以下固定白名单协议，主可继续保留现有模块调用：

```text
OpinionCapture-CLI.exe --web-worker xiaohongshu JOB_JSON
OpinionCapture-CLI.exe -B -m opinion_capture.web_xiaohongshu --worker JOB_JSON
OpinionCapture-CLI.exe -m opinion_capture.web_xiaohongshu --worker JOB_JSON
```

GUI EXE 的相同路由也在启动 GUI 之前识别；worker 自身写的证据文件与日志不改变。内部使用 `runpy.run_module(..., run_name='__main__')`，仅接受两个固定 WEB 模块，不支持任意 `-m` 或 `-c`。主负责该适配器源码的 base Python / site-packages 修复，本任务没有重复改动。

### B站 WEB / 私有会话 multiprocessing

- `multiprocessing.freeze_support()` 在 `entrypoint()` 中第一时间执行，先于 GUI/CLI 路由与 windowed 日志设置，支持 PyInstaller 的 `--multiprocessing-fork` 启动约定。
- 收集所有 `opinion_capture` 子模块，并显式列出 `android_results`、`web_results_bilibili`、`web_results_xiaohongshu`、`multiprocessing.spawn` 等动态入口。
- 离线校验器保留 multiprocessing 顶层探针：源码使用 base Python；冻结时分别选择两个 EXE 验证 spawn/Pipe/PID/退出。**源码探针已通过，冻结双入口探针没有执行。**
- 默认 GUI 不执行采集；主负责保证新增 session worker 在 import 时也不启动登录或采集。

## 5. 外部依赖发现与真实限制

**不打包 Chrome、Edge、MuMu、ADB 安装包，不打包浏览器用户 profile、账号、登录态、原始 docs 图片。** Playwright 的 Node 驱动和 uiautomator2 的 JAR/APK 资源属于适配器运行依赖，会收集；这不等于浏览器、模拟器、设备服务或账号已准备好。

依赖发现只检查路径存在，不运行浏览器、`adb devices`、MuMu 或网络请求：

1. 显式环境变量；
2. CLI `--dependencies JSON`，或 EXE 旁 `portable-dependencies.json`；
3. PATH / Chrome、Edge 常见安装目录；ADB 可从配置的 MuMu 根目录下有限候选寻找。

| JSON字段 | 环境变量 | 行为 |
|---|---|---|
| `browser` | `OPINION_CAPTURE_BROWSER` | 可指定 Chrome/Edge EXE；已只读核对两个WEB采集器及sessions登录处消费配置 |
| `adb` | `OPINION_CAPTURE_ADB` | 已只读核对 `AdbClient` 消费此变量；launcher同时设置 `ADBUTILS_ADB_PATH`，把父目录加到子进程 PATH |
| `mumu_home` | `OPINION_CAPTURE_MUMU_HOME` | 仅定位安装目录和有限 adb 候选，不启动模拟器 |

显式路径不存在时显示 `invalid`，不静默选择另一份依赖。JSON 相对路径相对于 JSON 所在目录；环境变量路径要求绝对路径。没有找到外部依赖不会让离线运行库检查虚报平台可用：报告始终带 `runtime_verified=false`。

已核对本机存在 Chrome 和 PATH 中的 ADB；没有枚举 MuMu 实例，没有检查登录，也没有因本检查启动任何平台。MuMu 根目录未配置时报告 `missing`，这不证明机器上未安装 MuMu。

终端用户仍需自行准备：

- 可兼容本版本 Playwright 的 Chrome/Edge；系统已有浏览器不等于平台访问成功。构建过程不会运行 `playwright install`，也不会复制 Playwright 下载浏览器缓存。

- 用户自己在专用会话/设备中完成平台登录。浏览器用户 profile、Cookie、账号和真实 `.local/plan.json` 均不进入分发。
