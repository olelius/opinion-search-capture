更新：2026-09-08。本文只记录导出、派生图和对应验证；采集器 TOP N、登录、调度状态和数据库生命周期由主执行链负责。

## 1. 已交付接口

### 批次预检

入口：`H:\Public Opinion Search Capture System\src\opinion_capture\export_plan.py`。

```python
preflight_plan(plan, *, planned_at=None, probe_writable=False) -> dict
```

- `plan` 可以是配置实例、普通属性对象或 Mapping；不要求 `.to_dict()`，不修改传入对象。
- `planned_at` 接受含时区的 `datetime`，转换为项目时区。省略时使用当前时刻；要得到确定性结果应显式传入。
- `probe_writable=False`：不创建批次、数据库、图片或目录，只读检查最近已有父目录、普通文件阻挡和 `os.access` 权限迹象。
- `probe_writable=True`：另在最近已有祖先目录排他建立短暂探针，写入、`fsync` 后清理；不创建计划目录树。
- 返回值均可 JSON 序列化：

| 字段 | 含义 |
|---|---|
| `ok` | 当前检查是否没有错误 |
| `errors` / `warnings` | 字典列表，元素至少含 `code`、`message`，可另含 `kind/path/index/field` |
| `raw_paths` / `originals` | 同一批全部任务的代表性原图路径；顺序为平台→端→种类→冻结关键词 |
| `composite_paths` / `composites` | 每组第一页的代表路径，附完整冻结成员和顺序 |
| `preview` | 原图与汇总代表路径合并列表 |
| `counts` | 任务数、组数、代表路径数，不是实际帧数或页数 |
| `composition` | 从属性/字典读取的布局参数及默认值 |
| `writable_checks` | 目标父路径、实际检查的祖先、是否真的做过探针 |
| `boundaries` | 给 GUI 展示的预检边界说明 |

默认配置兼容主 Plan：`composite_columns=4`、`composite_cell_width=1080`、`composite_layout='grid'`、`composite_max_pixels=50_000_000`、`composite_max_height=24000`。

**预检保证的范围**：白名单/格式校验、配置必需字段、路径穿越、保留字/非法字符、按 UTF-16 计数的保守路径上限、批内大小写折叠冲突、示例目标已存在、父路径被文件挡住、静态可写权限，以及可选真实写入探针。成功和 `partial` 的代表路径均校验长度及已有占用。

**预检不是未来唯一性证明**：所有任务故意使用同一示例 `capture_stamp`。`planned_at` 不是实际截图时间；预览 ID 是确定性展示代号，不预占真实 ID。预览 `batch=1`、`part=1` 不冒充数据库序号/最终帧页数。目录跨午夜/跨月、失败状态标签、后续写权限/空间变化，以及实际 ID 长度，均应在执行时重新校验。含 `{artifact_id}` 时，每一帧/页仍应由 runner 分配独立 ID。

未显式含年份、缺少独立产物 ID、缺少分页区分字段等作为结构性风险警告；已经确定的批内冲突作为错误。单次预检不扫描所有历史图片，也不把“未命中示例路径”解释为历史完全无冲突。

### 白名单模板与精确身份

入口：`H:\Public Opinion Search Capture System\src\opinion_capture\exporting.py`。

- 允许任意合法的用户字面文字与以下字段组合；字面大括号使用 `{{`、`}}`。
- 整数字段：`year/month/day/top_n/batch/part`，支持裸字段及 `02d`。
- 文本字段：`project/platform/client/display_type/keyword/keyword_id/content_label/capture_stamp/artifact_id`。
- 禁止表达式、属性访问、索引访问、转换符和任意格式表达式；文件名是单独的 PNG 文件名。
- 原图与合并图拥有互不依赖的目录/文件模板。
- `{keyword}` 显示清理后的文本并带 12 位摘要后缀；完整 `keyword_id()` 是原始 UTF-8 关键词 SHA-256。A1/A10/a1、非法字符清理后相似文字均分别处理。实际搜索词不被路径清理改写。
- `exact_group_key(..., captured_at=..., keyword=None)` 返回 `(年, 月, 日, 平台, 端, 种类)`；传入关键词则再附完整摘要。业务分组不做文件名子串搜索，不把同月不同年份或 APP/WEB 混为一组。
- 摘要文件后缀是实用防撞辅助，不是数学上的绝对唯一性证明；最终排他发布仍是必要保护。

## 2. 分页拼图

入口：`H:\Public Opinion Search Capture System\src\opinion_capture\imaging.py`。

```python
compose_pages(
    image_paths, output_dir, *, members=None,
    layout="grid", columns=4, cell_width=1080, gap=16,
    max_pixels=50_000_000, max_height=24000,
    max_input_pixels=50_000_000,
    filename_template="page_{part:02d}.png",
    output_path_factory=None,
) -> dict
```

### 输入与分页规则

1. `image_paths` 是冻结清单，允许 `None`；`members` 若传入则须一一对应，至少可传 `keyword/status`，其余元数据保留。
2. `success/partial` 且有文件时绘制图片；`failed/blocked/missing` 等状态绘制显式 `NO IMAGE / 缺少有效截图` 占位。受阻截图即使传入也不展示为有效内容；`partial` 明确标色。
3. 有成员清单时，每个单元上方新增序号、关键词和状态标签；中文优先复用系统微软雅黑/现有 CJK 字体，长标签换行，标签不盖在截图上。若系统缺少中文字体，英文状态和 JSON 原文仍是核对依据，中文显示需按运行环境检验。
4. 图片按宽度等比例缩小，宽度小于配置值的图片不放大。不按行高拉伸、不裁切边缘、不覆盖截图文字。单元高度由标签和完整图片共同决定。
5. `grid` 按行优先装入；`horizontal` 每页只有一行。每次加入完整单元都先核对像素和高度预算，超限则换行或换页，必要时少于指定列数。全部成员只出现一次，分页不丢关键词。
6. **单个完整单元独占一页仍超限时抛出 `ImagingError`**，并在写页之前报告。应由用户显式提高预算或选择更小宽度；模块不偷改清晰度、不横切文字、不猜测文字行边界。原图超过 `max_input_pixels` 时同样在解码前报告。
7. `output_path_factory(part)` 页号从 1 起，优先于模板，返回 `output_dir` 内的 PNG 绝对路径。简单文件模板接受 `part/page/index`（都从 1 起）及 `02d/03d/04d`，不接受目录结构或表达式。所有页的输出目标在第一张落盘前校验，含大小写折叠、已有文件、原图路径、越界和长度。

### 返回值

- 总结果：`pages/page_count/members/status/layout/cell_width/order/boundaries`。
- `pages` 各项保留原 `compose_grid` 的 `path/width/height/pixels/format/inputs/columns/placements`，增加 `publication/page/part/page_count/members/order`。
- `placements`：`index` 为组内全局零基序号，`order` 为一基序号，另含 `keyword/status/member/path/source_size/page/part/row/column/x/y/width/height/placeholder/card_box/label_box`。
- `x/y/width/height` 指截图内容区域；缺图时高度为 0，使用 `card_box/label_box` 定位占位标记。框坐标是 `[left, top, right, bottom]`，右/底边不包含。
- `member` 保留输入元数据；`status` 是实际渲染状态，例如声称成功但没有文件的成员会显示为 `missing`。顶层存在任何非成功成员则为 `partial`。

runner 接入时，按真实采集日期/平台/端/种类先分组，每组遍历冻结关键词，缺图填 `None`。`output_path_factory` 调用 `artifact_values(part=part, artifact_id=每页独立ID)` 再用合并图模板生成路径；新模板包含 `{part:02d}`，旧模板只有 `{artifact_id}` 时每页 ID 也须不同。

已有 `compose_grid` 继续可用，默认宽度对齐到 1080；`stitch_vertical` 的严格候选唯一性、低纹理检查及原分辨率 RGB 复核逻辑未改动，没有增加猜测拼接降级。

## 3. 不可变发布与故障边界

统一使用 `publish_immutable(staged, destination)`：

1. 原图复制到目标同目录独立 `.capture-*.tmp`；派生图先编码为 `.compose-*.tmp`。
2. 关闭前 flush/fsync；派生 PNG 在暂存路径完成 `Image.verify()`。
3. Windows 使用同目录 `os.rename` 的**不替换目标**行为发布，既不依赖硬链接，也不用会替换历史文件的 `os.replace`。
4. POSIX 使用 `os.link` 排他发布；不支持时直接报错，没有“最终文件先创建、再写一半”的降级。
5. `finally` 清理本次暂存文件；复制/编码/同步/校验失败时最终路径不出现部分文件。已存在目标、并发同名抢占均保留旧内容。

已在本机 Windows 验证原生发布、模拟硬链接不可用、24 次并发竞争只有一次成功，以及复制/同步/PNG 校验故障。未实测每种 FAT/exFAT 卷或网络共享，不将本机结果扩大为所有远程文件系统保证。

保证单位是**单个完整文件**，不是整个批次事务。后续页写入失败时，已发布完整页保留；整个函数抛错，runner 不应将全组记为完成。回退只针对本次明确记录的产物清单，严禁清理既有历史/原始证据。异常终止可能留下 `.tmp`，它们不属于已发布 PNG；断电持久性还受文件系统和存储设备影响，`fsync` 不冒充多文件事务或硬件级保证。
