# 滚动与重试规则

## 滚动

- 普通推进目标为有效内容区的80%，保留约20%重叠；接近TOP N时按缺失内容缩短末段，避免多翻页。
- 速度优先缩短手势和多余固定等待；截图仍需等当前内容就绪，重叠、身份及图片完整性判定保留。
- APP使用单条ADB shell发送触控序列：移动320ms＋末端静止180ms后抬起（谨慎模式400＋180ms），替代按450px/s计算的慢手势；移除固定0.6秒等待。设备命令开销另外计入`next_scroll.elapsed_seconds`，因此0.5秒是序列设定值而非实测单屏总耗时。
- WEB滚动从55%提高到80%；内容就绪后只保留60ms间隔的稳定对，不继续叠加250—500ms固定静置。长图像素/接缝验证继续保留。
- 加载未完成时原地等待，不把静止当作已经到底，不反复空滑；等待受本次任务总时限和取消信号约束。
- APP每次attempt共享最多25秒加载等待额度，新内容就绪即可提前继续；超时标记可重试。该额度包含设备读取/截图耗时，不在总采集超时之外追加。
- 手势距离/时长是控制参数，不是实测画面位移或整批性能承诺。

设备端触控动作使用现有`cmd input touchscreen motionevent`接口，参数与动作类型参照[Android官方实现](https://android.googlesource.com/platform/frameworks/base/+/80c54abf5a10/services/core/java/com/android/server/input/InputShellCommand.java)；未安装额外设备程序。

## 重试

- 默认`max_retries=1`、`retry_delay_seconds=2`，即首次失败后最多再试一次；用户已有配置保持原值。设为0即关闭自动重试。
- 仅暂时超时、连接或加载故障（或采集器明确标为可重试）进入有限重试。登录、风险拦截、取消、成功及不明身份/完整性问题不因状态不绿而盲重试。
- APP与WEB结果重试均重新搜索当前关键词，从首屏开始；浏览器会话/登录继续复用。WEB下拉词只重新展开/输入关键词，不先运行TOP N。
- 每次使用新的attempt、目录、帧列表和排名状态，失败18条与下一次2条不拼成20条。旧诊断与报告保留，汇总只使用本次最终结果。
- 手动恢复批次只执行未成功任务；已有完整哈希对应的成功图片直接复用。恢复过往失败任务也标记`fresh_search=true`。
- 报告新增`attempt_number`（跨恢复累计）、`retry_number`（本次执行内）、`fresh_search`、`retryable`、`retry_scheduled`、`retry_exhausted`和`retry_scope`。计划过重试后若用户取消，不再发起下一次采集。

## 交付边界

本轮修改源码，不生成EXE，不访问平台重复实拍；只做新逻辑及直接受影响路径的定点。去说明条修复继续保留。旧正式便携包不包含本轮修改，待用户确认全部修改结束后统一打包。

验证覆盖：快速手势次序/取消、模拟慢加载恢复与预算耗尽、WEB同词复用及重新导航、下拉清空重填、尾部限幅和原像素拼接、runner重试上限与旧帧隔离。实际设备执行耗时及页面动态加载仍以之后真实运行的报告为准，不把替身测试作为现场测速。
