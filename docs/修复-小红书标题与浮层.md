## 接口与实现约定

### 笔记字段

`parse_page(xml, platform, kind, keyword)` 签名不变：

- `_note_structure` 同时服务笔记解析与页尾判断，以半宽卡片内大封面结构识别内容，不依赖混淆 ID 是否包含 `title/cover`。带此结构的卡片即使字段不完整，也留待解析或 `unknown`，不当作页尾。
- `title` 仅取正文容器直接子 TextView：位于封面下方、作者上方且在封面横向范围内；排除独立促销标签。时长只在封面内部识别，正文自身即使是时间格式仍保留。零个或多个候选、多个冲突时长均保留 `unidentified_note_card`。
- `duration` 只取封面矩形内、符合时间格式的独立文本；未显示则为空字符串，不回填到正文。
- `identity_kind="visible_title_author"`；指纹继续使用原四段格式 `SHA256(platform + 分隔符 + title + 分隔符 + author + 分隔符 + "")`，明确不纳入时长和促销标签。不同正文即使同作者、同时长也有不同指纹。
- `promoted` 由直接子文本中的独立“广告 / 赞助 / 推广 / 品牌合作”标签判定，正文提及这些词不自动标成推广；推广笔记保留。frame011 的真实广告卡用于字段分离检查。
- 身份仍是可见内容指纹，`platform_content_id=None`，不声称取得平台笔记 ID 或全局唯一性；原有身份冲突/重排检查保留。

### 可见区域与遮挡清单

所有页面均有 `occlusions` 列表，无识别遮挡时为空。本轮只识别小红书结果列表外、底部紧凑可点击容器中三组提示文案同时出现的快捷方式提示；普通笔记提及同样文字不触发。

frame014 输出：

```python
page["viewport"] == [0, 210, 1080, 1721]
page["occlusions"][0]["reason"] == "search_shortcut_prompt"
page["occlusions"][0]["bounds"] == [26, 1721, 1054, 1833]
# texts 保存识别到的真实文案，包含副标题原有的截断尾部。
```

- 可见内容底边收缩到提示容器顶部，不只收缩到文字顶部，也不保留浮层下方碎片作为连续可见区。
- 条目完整性、未知边缘与锚点范围沿用收缩后的 viewport；原卡片 bounds 保持原始坐标。
- 浮层独立记录，不计为笔记；frame015 无提示时底边恢复为 1920。
- `page_signature` 包含 `occlusions`，并纳入与稳定身份分离的 `duration/promoted`，防止双 XML 配对漏掉遮挡或字段变化。
- 不删除、遮盖、绘制或重编码原截图。现有拼接仍仅使用每帧有效 viewport，原始证据持续保留。

### 零位移与主采集器交接

`match_frames(previous, current, check=...)` 签名及成功返回结构不变，新增：

```python
raise EvidenceError("no_scroll_progress")
```

- 只有达到原可靠锚点数量/分布要求，并且全部共同唯一完整卡片及共同唯一文字锚点的 bounds 严格一致时触发；不仅检查中位数为零。
- 文字锚点多数位移共识的原门槛保留；少数非零证据即使被共识排除，也阻止降级为 `no_scroll_progress`。
- 水平位置变化、尺寸变化、混合位移、负向位移继续走原异常；正向位移仍进入原像素复核。像素误差、重叠高度、纹理、相邻一像素区分度与排名检查保持原逻辑。
- 新异常在读取 PNG 拼接前抛出，不返回零位移链接，不更改排名、偏移或结束标记。
- 主会拟在 `android.py` 使用有效 viewport 内 72%→约47%、小红书 x=75% 的手势，并仅捕获该精确错误，最多两次换内容区拖动。此处只约定交接接口，不将主会待完成代码或设备验证记为已完成。
