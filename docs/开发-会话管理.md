# WEB 正常会话管理

更新：2026-09-08。本切片只维护 `sessions.py`、`test_sessions.py` 和本文；Plan、runner、GUI、平台适配器、打包入口由主集成。未执行 Git 提交。

## 接口与接入

```python
from opinion_capture.sessions import profile_directory, open_web_login

profile = profile_directory(plan, "bilibili")  # Path；只计算，不创建目录
result = open_web_login(
    plan, "xiaohongshu", cancel_event=cancel_event, timeout_seconds=1800,
)
```

- `platform` 使用内部标识 `bilibili` / `xiaohongshu`，不依据名称猜测平台。
- `profile_directory(plan, platform) -> Path`：返回解析后的绝对路径；无效平台、相对根目录、通用浏览器路径、与导出目录互相包含时抛 `ValueError`。
- `open_web_login(plan, platform, *, cancel_event=None, timeout_seconds=1800) -> dict`：同步阻塞接口，仅在用户明确点击管理会话后由 GUI 工作线程调用。模块导入、配置预览、路径计算都不会启动浏览器。超时接受 `(0, 1800]` 的有限数值，不接受 bool。
- GUI 取消按钮仅设置同一 `threading.Event`；继续等工作线程返回，之后再显示完成或释放界面占用。不要强杀 GUI 线程。
- runner 采集请求的 `user_data_dir` 使用 `str(profile_directory(plan, platform))`。本模块不导入 runner。

### 返回值

| 字段 | 语义 |
|---|---|
| `status` | `success` / `blocked` / `failed` / `cancelled` |
| `outcome` | `authenticated_session_ready` / `manual_session_closed` / `busy` / `timeout` / `cancelled` / `incomplete`；小红书平台阻塞可为 `blocked` |
| `reason` | 生命周期原因或适配器原有诊断原因，供本地提示 |
| `authentication_verified` | 默认`False`；小红书“我”导航或B站同源可见账号资料链接/头像等明确页面证据出现时为`True`；不读取Cookie |
| `session_persisted` | 认证确认且正常关闭自有持久上下文后为`True`，与采集计划JSON是否保存分开 |
| `busy` | 活动资源锁占用时为 `True` |
| `profile_dir` | 本平台专属目录；参数校验失败时可为 `None` |
| `diagnostic_dir` / `log_path` | 本次本地诊断目录 / `session.json`；提前取消、锁忙、参数失败时可为 `None` |
| `started_at` / `finished_at` / `elapsed_seconds` | 带时区的起止时间，以及 monotonic 实际耗时 |

`success + manual_session_closed` 只意味着手动窗口结束，提示为“浏览器会话已保留，登录未确认”。`authenticated_session_ready + authentication_verified + session_persisted` 显示“平台登录已确认；浏览器会话已保存”。已登录时无需再让用户关闭一次窗口；登录入口始终有界面，后续无头采集沿用同一profile。验证码、平台风险保持原有blocked，不自动处理。

## 路径、隐私与历史

- 默认 profile 根：`paths.application_root() / ".local" / "browser-profiles"`。源码运行定位仓库，冻结运行定位 EXE 目录，不受启动工作目录影响。
- `Plan.browser_profile_root` 为可选自定义根；平台目录是在其下追加内部标识。旧 Plan 对象缺少该字段时也采用默认根。
- 图片导出根不参与 profile 路径计算；更换图片接收/导出位置不更换会话。profile 与图片输出目录互不包含，链接解析后同样检查。
- 诊断仅在 `application_root()/.local/session-log/<platform>-<uuid>/`，包括取消标记、工作进程日志和会话摘要；也检查其与导出、profile 目录互不包含。
- 返回值过滤掉适配器的图片清单、Cookie 等其他字段。本模块不调用 `cookies()` / `storage_state()`、不导出会话，不向图片接收方传递浏览器数据。
- 不读取通用 Chrome/Edge profile。B站复用 `_prepare_profile` 的 `.opinion-capture-bilibili-profile.json`；小红书复用 `open_login` 内的 `.opinion-capture-exclusive` 检查。
- 不搬移、不删除、不清空旧目录。旧导出目录内遗留的历史会话保持原样，既不会自动认领也不会偷偷迁移；历史文件仍应按其原有本地保留规则处理。

## 资源所有权与取消

锁键严格为：

```python
"browser-profile:" + str(profile_directory(plan, platform)).casefold()
```

`ResourceLock(..., timeout=0)` 与 runner 共锁。占用时立即 `blocked/busy`，不排队、不抢占、不创建 profile。锁保持到实际清理返回；锁文件存在本身不代表活动占用。

### 小红书：只接已有入口

直接调用 `web_xiaohongshu.open_login(profile, timeout_seconds=剩余总预算, cancel_file=本次标记, output_dir=本地诊断目录)`，不修改适配器函数、不猴补、不再套第二层浏览器监督。短周期桥接线程只检查线程事件/总期限并写取消文件，退出时同步 `join()`，不遗留后台监听线程。

适配器负责其工作进程、驱动和浏览器的真实退出、显式浏览器路径、frozen/redirector 启动与驱动临时路径；这些由主在适配器内集成。本接口的 mock 验证不等同于这些适配器路径的端到端验收。

### B站：专属可见浏览器

- `multiprocessing.get_context("spawn")` 创建工作进程；不是把冻结 EXE 当通用 `python -m` 使用。Windows venv 路径由 CPython spawn 处理 redirector。
- Windows：父进程创建 Job、启动等待门闩的工作进程、`assign(pid)`，成功后才放行。Job 设置 `KILL_ON_JOB_CLOSE`；即使根工作进程已退出，仍回收其浏览器后代。
- POSIX：工作进程在门闩前 `setsid()`，关闭时仅操作其进程组；本轮未在 POSIX 系统实测。
- B站正常 Playwright 持久 context 使用 `headless=False`，只导航首页，不填凭据。用短周期 `wait_for_timeout` 分发关闭事件，用户关闭包括导航中关闭只记录 `manual_session_closed`。
- `OPINION_CAPTURE_BROWSER` 显式设置时必须是有效绝对文件路径；错误/空值直接报错，不降级。未设置时只查已安装的浏览器候选，不自动下载。
- 超时覆盖启动、导航、用户等待和 context 关闭。取消/期限到达后给 context 最多 0.5 秒正常关闭窗口，随后强制回收并等待；总耗时可有有限的系统清理尾延迟。
- Job 清理先枚举**本 Job**成员并保留等待句柄，再终止所有成员、等待句柄结束并验证成员计数清零。仅有 `active=0` 曾被本地探针证明不足以保证所有进程句柄都已结束。等待上限为 5 秒，失败明确返回错误，不记作正常完成。

### 主集成可复用的最小 Windows Job 接口

```python
from opinion_capture.sessions import _WindowsJob

job = _WindowsJob()             # 仅 Windows，创建带 KILL_ON_JOB_CLOSE 的 Job
try:
    job.assign(pid)             # (pid: int) -> None；子进程仍在启动门闩等待
    # assign 成功后才放行；由调用方监督取消/期限，并最终等待直接子进程
    job.terminate()             # () -> None；同步清理全部成员，不释放 Job 句柄
finally:
    job.close()                 # () -> None；幂等，清理成员并释放句柄
```

系统错误抛 `OSError`，清理等待超时抛 `TimeoutError`。进程退出的所有路径都应执行 `close()`，根 PID 已退出时也须调用。调用方仍须 `wait/join` 直接子进程，持有 profile 锁到清理结束。该私有类当前只依赖标准库，sessions 顶层不导入平台模块，供主最小复用；未来若更多适配器共享，可再集中到进程控制模块，本切片不扩大写范围。
